# Agent Mode - RAG Q&A Portfolio - Design Spec (2026-07-05)

## Goal

Add an "Agent mode" to Zane Wang's portfolio: a ChatGPT-style Q&A experience where any
visitor can ask questions about Zane ("who are you", "your hardest project", "why did you
move from electrical engineering to software") and get grounded, streamed answers.
The existing Swiss portfolio becomes the "browse mode", one toggle away.

This is deliberately a real vector-RAG showcase, echoing Zane's own UQ Ask Anything project,
so recruiters see consistent engineering judgement (grounding, citations, deterministic
boundaries, answerability gating).

## Decisions (locked)

- RAG type: real vector retrieval, treated as a technical showcase.
- Hosting: Cloudflare, via `@opennextjs/cloudflare` (Workers). next-on-pages is deprecated.
- Vector store: Cloudflare Vectorize (native binding).
- Embeddings: Workers AI `@cf/baai/bge-m3` (same family as UQ Ask Anything / Study Pilot).
- Generation LLM: DeepSeek API, proxied through Cloudflare AI Gateway (cache + rate limit + analytics). DeepSeek is already a supported backend in UQ Ask Anything.
- Knowledge base: a new, richer, first-person KB (not the terse marketing copy in data.ts).
- Entry: Chat is the default homepage `/`; portfolio lives at `/portfolio`; header toggle switches.
- Language: English only (UI, KB, answers).
- Delivery order: get the full chain working locally end to end first, then deploy to Cloudflare.

## Architecture and routing

```
Cloudflare Workers (OpenNext)
  /            -> Agent mode (default, ChatGPT-style)   [homepage]
  /portfolio   -> existing Swiss portfolio (browse mode)
  /api/chat    -> RAG endpoint (streaming SSE)
  Header toggle: [ Ask me  <->  Portfolio ]
```

- The existing Swiss single page moves verbatim to `/portfolio`; its logic is unchanged, only its route location moves.
- `/` is a new Agent page: centered headline + ChatGPT-style input + starter-question chips. It strictly reuses the existing Swiss design tokens (near-black ground, ivory ink, blue `#5c7cff`, Schibsted Grotesk). No second visual system, no third-party chat widget look.
- Both modes share one header toggle and have independent URLs, so SEO and sharing hold.

## RAG pipeline (real vector retrieval)

Offline (build/deploy time):

```
KB markdown files -> chunk -> bge-m3 embedding (Workers AI) -> upsert into Vectorize
```

Online (per question):

```
question -> bge-m3 embed -> Vectorize top-k -> answerability gate -> DeepSeek (grounded, with citations) -> SSE stream
```

Design choices, deliberately mirroring UQ Ask Anything:

1. Answerability gate: if the top-k best similarity is below a threshold, do not force an answer. Politely refuse ("I can only answer questions about Zane's background and projects") and offer starter questions. This is both an engineering highlight and an abuse guard.
2. Citations: every answer carries the KB source chunks it used (e.g. "Source: Project - Piggy Way"), expandable to the underlying text. Demonstrates grounded-by-design.
3. Deterministic boundary: contact facts (email, phone, GitHub, resume link) are returned by deterministic code, never generated by the model.
4. Multi-turn: continuous back-and-forth; conversation history lives client-side and is sent with each request. The server is stateless (serverless-friendly, no chat database).

## Chat UI/UX

- Empty state: centered one-line headline ("Ask me anything about Zane"), a large input, and 4 starter chips (who are you / hardest project / why switch from electrical engineering / which clouds do you know). Clean, ChatGPT-like.
- Conversation state: headline collapses on first submit; messages flow top to bottom; answers stream token by token; input pinned at the bottom.
- Answer block: Markdown rendering (code blocks, lists, bold), with a light "Source: ..." citation row at the end, expandable to raw chunk text.
- Interactions: Enter to send, Shift+Enter for newline, stop generation, copy answer, regenerate. Typing caret while loading.
- Visual: 100% reuse of existing Swiss tokens, no new fonts/colors. Answer typography follows the existing dl/hairline language so it reads like "the portfolio speaking", not an embedded widget.
- Degradation: with `prefers-reduced-motion`, disable the streaming typewriter animation; with no JS, `/` renders an SSR static intro that links to `/portfolio`.

## Abuse and cost protection (public site)

- Turnstile: verify before the first message (already used in Piggy Way), blocks bots.
- AI Gateway: DeepSeek routed through AI Gateway for response caching (repeat questions do not burn spend), rate limiting, and usage dashboards.
- Server-side limiting: simple per-IP rate limit (e.g. N messages/min), input length cap, plus the answerability gate to drop off-topic questions.
- Secrets: DeepSeek key stored as a Worker secret, never shipped to the frontend.

## Content / knowledge base

- KB is a set of markdown files under `src/content/kb/*.md`, split by topic: personal intro, one deep-dive per project, each role, tech-choice opinions, the career-switch story, and an FAQ.
- Claude drafts the first version from the resume PDF plus current data.ts, flagging places that need Zane's real details (switch motivation, war stories, opinions). Once Zane edits, the KB is the source of truth.
- A build-time script handles chunking + embedding + upsert into Vectorize.

## Deployment / known risks

- `@opennextjs/cloudflare` runs Next 16 App Router (next-on-pages is deprecated). This is the single main technical risk: Next 16 is very new and the OpenNext adapter needs real testing. Fallback if blocked: make the chat a plain Workers function plus a static frontend. The implementation plan makes "verify OpenNext + Next 16 runs on Cloudflare" the first milestone to de-risk early.
- Bindings: Workers AI (bge-m3), Vectorize, AI Gateway. Secrets: DeepSeek key, Turnstile key.

## Delivery milestones (order)

1. Local end-to-end: RAG + chat UI working locally (dev may use in-memory cosine as a Vectorize stand-in), validate the experience.
2. Author + refine the KB with Zane; finalize chunking and retrieval quality.
3. Move to Cloudflare: OpenNext build, Vectorize seed, Workers AI + AI Gateway bindings, Turnstile, secrets, deploy.

## Success criteria

- Asking a covered question returns a grounded, streamed answer with correct citations.
- Asking an off-topic question triggers the answerability refusal, not a hallucination.
- Contact facts always come from deterministic code, matching data.ts exactly.
- `/` defaults to chat, `/portfolio` shows the unchanged Swiss site, toggle works both ways.
- Renders correctly at 390px and 1440px, no horizontal scroll, no console errors.
- No exposed secrets; Turnstile + rate limit active in production.
- `pnpm lint` and `pnpm build` pass clean.
